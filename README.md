# RAWDA — منصة روضة لإدارة الحضانات

الإصدار `0.9.1` — حزمة مشروع عربية متعددة الحضانات (Multi-tenant)، مبنية بـ Next.js وSupabase. هذه حزمة مصدر جاهزة للإعداد والنشر بعد إنشاء الخدمات السحابية وربط مفاتيحها؛ ليست خدمة مستضافة مسبقاً.

## الوظائف الموجودة في الحزمة

- واجهة ويب عربية RTL متجاوبة.
- تسجيل الدخول وإنشاء حضانة وربط أول مدير بها.
- إدارة الأطفال والفصول والالتحاق.
- ربط حسابات المعلمات وأولياء الأمور الموجودين مسبقاً.
- تسجيل الحضور والغياب والتأخر.
- بوابة ولي الأمر لمتابعة الطفل والحضور والدروس والتقييمات والإعلانات.
- إدارة المواد والكتب (بيانات وصفية) والدروس اليومية.
- تسجيل تقييمات المهارات وتقارير تقدم قابلة للطباعة من المتصفح.
- مخطط PostgreSQL وسياسات Row Level Security متعددة المستأجرين.
- مصادقة البريد الإلكتروني بكلمة المرور أو رابط دخول لمرة واحدة (OTP).
- تسجيل الدخول بواسطة Google OAuth عبر Supabase Auth (يتطلب إعداد بيانات المزود).
- مسار OAuth callback لتبادل رمز الدخول وإنشاء جلسة آمنة.
- طلب ربط ولي الأمر بالطفل باستخدام معرّف الحضانة وكود الطفل، مع موافقة إدارية قبل كشف بيانات الطفل.

## متطلبات التشغيل

- Node.js 20 أو أحدث وnpm.
- حساب Supabase لإنشاء قاعدة البيانات والمصادقة.
- حساب Vercel (أو استضافة تدعم Next.js) للنشر.

## إعداد قاعدة البيانات لأول مرة

أنشئ مشروعاً جديداً في Supabase، ثم افتح **SQL Editor** ونفّذ ملفات المخطط والترحيلات بالترتيب الموثق في مجلد `supabase/`. في مشروع RAWDA المرتبط، الترحيلات مسجلة حتى `014_rls_initplan_optimization`. لا تعِد تشغيلها على قاعدة بيانات مهيأة.

استخدم مشروعاً جديداً فارغاً لتجنب تعارض الجداول والسياسات. لا تشغّل `seed-demo.sql` على قاعدة بيانات الإنتاج؛ فهو بيانات اختبار.

## إعداد التطبيق محلياً

```bash
npm install
cp .env.example .env.local
```

من لوحة Supabase افتح **Project Settings → API** وانسخ Project URL وPublishable/anon key إلى `.env.local`:

```env
NEXT_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=YOUR_SUPABASE_ANON_OR_PUBLISHABLE_KEY
```

ثم شغّل:

```bash
npm run dev
```

افتح `http://localhost:3000`، أنشئ حساباً بالبريد الإلكتروني من صفحة الدخول، ثم أكمل إعداد الحضانة. في بيئة الإنتاج اضبط إعدادات **Authentication → URL Configuration** على رابط الموقع المنشور وروابط إعادة التوجيه المناسبة.

### إعداد البريد الإلكتروني وGoogle

1. من Supabase افتح **Authentication → Providers → Email**، وفعّل Email provider. فعّل تأكيد البريد الإلكتروني للإنتاج واضبط SMTP مخصصاً.
2. في **Authentication → Providers → Google** فعّل Google، وأدخل OAuth Client ID وClient Secret من Google Cloud Console.
3. أضف عنوان Callback الذي يعرضه Supabase إلى Authorized redirect URIs في Google Cloud.
4. في Supabase **Authentication → URL Configuration** اجعل Site URL رابط الموقع المنشور، وأضف `https://YOUR_DOMAIN/auth/callback` و`http://localhost:3000/auth/callback` إلى Redirect URLs.
5. لا تضع Google Client Secret أو Supabase service role key في متغيرات `NEXT_PUBLIC_*`.

## النشر على Vercel

1. استورد مستودع RAWDA في Vercel واختر Next.js.
2. أضف `NEXT_PUBLIC_SUPABASE_URL` و`NEXT_PUBLIC_SUPABASE_ANON_KEY` في إعدادات المشروع.
3. نفّذ Deploy بعد نجاح فحوص GitHub Actions.
4. أضف نطاق الموقع في Vercel، ثم أضف النطاق نفسه إلى Supabase Auth → URL Configuration.
5. اختبر إنشاء الحساب، تسجيل الدخول، إنشاء الحضانة، وربط المعلمة وولي الأمر.

## الأدوار

- `platform_admin`: إدارة المنصة المركزية (تحتاج أدوات تشغيل إدارية إضافية قبل تقديمها كلوحة SaaS تشغيلية كاملة).
- `nursery_admin`: مدير الحضانة.
- `academic_supervisor`: المشرف الأكاديمي.
- `teacher`: المعلمة، وتقتصر صلاحيات التقييم والدروس على الفصول المسندة لها وفق السياسات.
- `parent`: ولي الأمر، وتقتصر البيانات على الطفل المرتبط به مع `can_view_reports=true`.

## نقاط تتطلب استكمالاً قبل الاستخدام التجاري

- لم يتم التحقق من نشر موقع Vercel أو ربط نطاق إنتاجي.
- مزود Google OAuth وSMTP يحتاجان إدخال بياناتهما من لوحة Supabase؛ لا يمكن إنشاء هذه الأسرار من المستودع.
- صفحة إدارة المعلمات وأولياء الأمور تربط حسابات Auth الموجودة مسبقاً؛ دعوات البريد وإنشاء الحسابات من لوحة المدير تحتاج إعداد تدفق دعوات موثوق.
- مكتبة الكتب تحفظ البيانات الوصفية فقط؛ واجهة رفع ملفات PDF وتخزينها في Supabase Storage لم تُنفّذ بعد.
- التقارير الحالية قابلة للطباعة من المتصفح؛ تصدير PDF مخصص آلياً غير مضاف.
- لوحة المنصة المركزية، الاشتراكات والفوترة، الإشعارات (SMS/WhatsApp/Email)، النسخ الاحتياطي، ومراقبة الأخطاء تحتاج استكمالاً.
- يلزم اختبار سياسات RLS عملياً بحسابات منفصلة لكل دور وعلى أكثر من حضانة قبل إدخال أي بيانات أطفال حقيقية.

## حماية البيانات

لا تضع `SUPABASE_SERVICE_ROLE_KEY` في متغيرات `NEXT_PUBLIC_*` أو في كود المتصفح. لا تستخدم بيانات أطفال حقيقية في Demo. فعّل المصادقة متعددة العوامل لحسابات الإدارة، واستخدم كلمات مرور قوية، واختبر عزل بيانات كل حضانة وكل ولي أمر قبل الإطلاق.

## RAWDA 2.0 — حالة قاعدة البيانات

تم تهيئة مشروع Supabase المرتبط وتطبيق الترحيلات حتى `014_rls_initplan_optimization`.

- `001` إلى `009`: المخطط الأساسي والحسابات والأدوار والحضور وبوابة ولي الأمر والمناهج والتقييمات وطلبات الربط.
- `010_rawda_security_function_grants`: منع تنفيذ الدوال الحساسة من الدور المجهول.
- `011_nursery_city`: حفظ مدينة الحضانة عند التأسيس.
- `012_scope_attendance_and_lessons`: تحديد الوصول للحضور والدروس حسب الفصل وفترة القيد.
- `013_foreign_key_indexes`: فهارس المفاتيح الخارجية.
- `014_rls_initplan_optimization`: تحسين تقييم `auth.uid()` داخل سياسات RLS.

تمت مراجعة الدوال العشر ذات `SECURITY DEFINER`: تنفيذها ممنوع عن `anon`، وتتضمن فحوص هوية/دور المستخدم في مسارات العمليات الحساسة. يبقى تنبيه Supabase عليها للمراجعة الدورية لأن المستخدمين المسجلين يحتاجون بعض هذه الدوال في سياسات RLS وعمليات التطبيق. كما تظهر ملاحظات أداء تتعلق بتعدد سياسات RLS والفهارس غير المستخدمة؛ لا تحذف الفهارس قبل وجود حمل استخدام وقياسات فعلية.

### فحوص البناء

يعمل GitHub Actions على تشغيل `npm run typecheck` و`npm run build` لكل تحديث في فرع التطوير. نجاح هذين الفحصين لا يثبت وحده نجاح تسجيل الدخول أو عزل بيانات الحضانات أو أن الموقع منشور.

### متطلبات ما قبل الإطلاق التجاري

اختبار الأدوار والعزل بين حضانتين بحسابات فعلية واختبارات RLS، وضبط Google OAuth والبريد على النطاق النهائي، وإكمال تخزين ملفات PDF والصور في Storage خاص، ولوحة إدارة المنصة المركزية والاشتراكات والفوترة والإشعارات، ثم النشر والتحقق من الموقع.

لا تعتبر هذه النسخة خدمة منشورة أو جاهزة لاستقبال بيانات أطفال حقيقية قبل إكمال بوابات الإطلاق أعلاه.
