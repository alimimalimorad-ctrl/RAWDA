# RAWDA — منصة روضة لإدارة الحضانات

الإصدار `0.9.1` — حزمة مشروع عربية متعددة الحضانات (Multi-tenant)، مبنية بـ Next.js وSupabase. هذه حزمة مصدر جاهزة للإعداد والنشر بعد إنشاء الخدمات السحابية وربط مفاتيحها؛ ليست خدمة مستضافة مسبقاً.

## الوظائف الموجودة في الحزمة

- واجهة ويب عربية RTL متجاوبة.
- تسجيل الدخول وإنشاء حضانة وربط أول مدير بها.
- إدارة الأطفال والفصول والالتحاق.
- ربط حسابات المعلمات وأولياء الأمور الموجودين مسبقاً.
- تسجيل الحضور والغياب والتأخر.
- بوابة ولي الأمر لمتابعة الطفل والحضور والدروس والتقييمات والإعلانات.
- إدارة المواد والكتب (بيانات وصفية) والدروس اليومية.
- تسجيل تقييمات المهارات وتقارير تقدم قابلة للطباعة من المتصفح.
- مخطط PostgreSQL وسياسات Row Level Security متعددة المستأجرين.
- مصادقة البريد الإلكتروني بكلمة المرور أو رابط دخول لمرة واحدة (OTP).
- تسجيل الدخول بواسطة Google OAuth عبر Supabase Auth.
- مسار OAuth callback لتبادل رمز الدخول وإنشاء جلسة آمنة.
- طلب ربط ولي الأمر بالطفل باستخدام معرّف الحضانة وكود الطفل، مع موافقة إدارية قبل كشف بيانات الطفل.

## متطلبات التشغيل

- Node.js 20 أو أحدث وnpm.
- حساب Supabase لإنشاء قاعدة البيانات والمصادقة.
- حساب Vercel (أو استضافة تدعم Next.js) للنشر.

## إعداد قاعدة البيانات لأول مرة

أنشئ مشروعاً جديداً في Supabase، ثم افتح **SQL Editor** ونفّذ الملفات بالترتيب التالي، كل ملف كاملاً:

1. `supabase/schema.sql`
2. `supabase/002_onboarding.sql`
3. `supabase/003_staff_guardians.sql`
4. `supabase/004_attendance.sql`
5. `supabase/005_parent_portal.sql`
6. `supabase/006_curriculum.sql`
7. `supabase/007_assessments_reports.sql`
8. `supabase/008_parent_auth_linking.sql`
9. `supabase/009_fix_classroom_tenant_fk.sql` (إصلاح مفتاح ربط الفصول بالحضانة)

استخدم مشروعاً جديداً فارغاً لتجنب تعارض الجداول والسياسات. لا تشغّل `seed-demo.sql` على قاعدة بيانات الإنتاج؛ فهو بيانات اختبار.

## إعداد التطبيق محلياً

```bash
npm install
cp .env.example .env.local
```

من لوحة Supabase افتح **Project Settings → API** وانسخ Project URL وPublishable/anon key إلى `.env.local`:

```env
NEXT_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=YOUR_SUPABASE_ANON_OR_PUBLISHABLE_KEY
```

ثم شغّل:

```bash
npm run dev
```

افتح `http://localhost:3000`، أنشئ حساباً بالبريد الإلكتروني من صفحة الدخول، ثم أكمل إعداد الحضانة. في بيئة الإنتاج اضبط إعدادات **Authentication → URL Configuration** على رابط الموقع المنشور وروابط إعادة التوجيه المناسبة.

### إعداد البريد الإلكتروني وGoogle

1. من Supabase افتح **Authentication → Providers → Email**، وفعّل Email provider. فعّل تأكيد البريد الإلكتروني للإنتاج واضبط SMTP مخصصاً (لا تعتمد على خدمة البريد التجريبية ذات الحدود المحدودة).
2. في **Authentication → Providers → Google** فعّل Google، وأدخل OAuth Client ID وClient Secret من Google Cloud Console.
3. أضف عنوان Callback الذي يعرضه Supabase (عادةً `https://YOUR_PROJECT.supabase.co/auth/v1/callback`) إلى Authorized redirect URIs في Google Cloud.
4. في Supabase **Authentication → URL Configuration** اجعل Site URL رابط Vercel النهائي، وأضف `https://YOUR_DOMAIN/auth/callback` و`http://localhost:3000/auth/callback` إلى Redirect URLs.
5. لا تضع Google Client Secret أو Supabase service role key في متغيرات `NEXT_PUBLIC_*`.

## النشر على Vercel

1. ارفع مجلد المشروع إلى مستودع Git خاص تملكه.
2. استورد المستودع في Vercel واختر Next.js.
3. أضف متغيري البيئة السابقين في إعدادات المشروع (Production وPreview عند الحاجة).
4. نفّذ Deploy.
5. أضف نطاق الموقع في Vercel، ثم أضف النطاق نفسه إلى Supabase Auth → URL Configuration.
6. اختبر إنشاء الحساب، تسجيل الدخول، إنشاء الحضانة، وربط المعلمة وولي الأمر.

## الأدوار

- `platform_admin`: إدارة المنصة المركزية (تحتاج أدوات تشغيل إدارية إضافية قبل تقديمها كلوحة SaaS تشغيلية كاملة).
- `nursery_admin`: مدير الحضانة.
- `academic_supervisor`: المشرف الأكاديمي.
- `teacher`: المعلمة، وتقتصر صلاحيات التقييم والدروس على الفصول المسندة لها وفق السياسات.
- `parent`: ولي الأمر، وتقتصر البيانات على الطفل المرتبط به مع `can_view_reports=true`.

## نقاط تتطلب استكمالاً قبل الاستخدام التجاري

- لم يتم إنشاء حساب Supabase أو Vercel أو نطاق باسم المستخدم؛ لا توجد مفاتيح اتصال في الحزمة.
- صفحة إدارة المعلمات وأولياء الأمور تربط حسابات Auth الموجودة مسبقاً؛ دعوات البريد وإنشاء الحسابات من لوحة المدير تحتاج إعداد تدفق دعوات موثوق.
- مكتبة الكتب تحفظ البيانات الوصفية فقط؛ واجهة رفع ملفات PDF وتخزينها في Supabase Storage لم تُنفّذ بعد.
- التقارير الحالية قابلة للطباعة من المتصفح؛ تصدير PDF مخصص آلياً غير مضاف.
- لوحة المنصة المركزية، الاشتراكات والفوترة، الإشعارات (SMS/WhatsApp/Email)، النسخ الاحتياطي، ومراقبة الأخطاء تحتاج إعداداً منفصلاً.
- طلب ربط الطفل ينشئ طلباً pending؛ يلزم توفير شاشة مراجعة إدارية تستدعي `review_parent_link_request(request_id, approve)` أو تنفيذ المراجعة من بيئة إدارية موثوقة قبل الاستخدام التشغيلي.
- يلزم اختبار سياسات RLS عملياً بحسابات منفصلة لكل دور وعلى أكثر من حضانة قبل إدخال أي بيانات أطفال حقيقية.
- يلزم تنفيذ `npm install` ثم `npm run typecheck` و`npm run build` في بيئة متصلة بالحزم قبل اعتماد الإنتاج.

## حماية البيانات

لا تضع `SUPABASE_SERVICE_ROLE_KEY` في متغيرات `NEXT_PUBLIC_*` أو في كود المتصفح. لا تستخدم بيانات أطفال حقيقية في Demo. فعّل المصادقة متعددة العوامل لحسابات الإدارة، واستخدم كلمات مرور قوية، واختبر عزل بيانات كل حضانة وكل ولي أمر قبل الإطلاق.


## RAWDA 2.0 — قاعدة البيانات والتهيئة

تم تهيئة مشروع Supabase المرتبط وتطبيق الترحيلات بالترتيب حتى `012_scope_attendance_and_lessons`.

- `001_rawda_initial_schema`: الجداول الأساسية متعددة الحضانات وسياسات RLS الأولية.
- `002` إلى `009`: الحسابات والأدوار والحضور وبوابة ولي الأمر والمناهج والتقييمات وطلبات الربط.
- `010_rawda_security_function_grants`: تقييد تنفيذ الدوال الحساسة عن المستخدم المجهول.
- `011_nursery_city`: حفظ مدينة الحضانة عند التأسيس.
- `012_scope_attendance_and_lessons`: إزالة سياسات متداخلة وتحديد الوصول حسب الفصل وفترة القيد.

قاعدة البيانات مهيأة لكنها لا تحتوي حسابات أو سجلات حضانة بعد. لا تشغّل `seed-demo.sql` على بيانات الإنتاج، ولا تضع مفتاح `service_role` في متغيرات `NEXT_PUBLIC_*`.

### تشغيل التطبيق

1. استخدم Node.js 20 أو أحدث.
2. انسخ `.env.example` إلى `.env.local` وأدخل عنوان Supabase ومفتاح Publishable/Anon العام فقط.
3. شغّل `npm install` ثم `npm run dev` للتطوير أو `npm run build` للبناء.
4. اضبط عناوين إعادة التوجيه في Supabase Auth وفعّل Google OAuth بعد إعداد بيانات مزوّد Google.

### تحديثات التطوير 0.9.1

- إضافة شاشة إدارية لمراجعة طلبات ربط أولياء الأمور والموافقة عليها أو رفضها.
- إضافة فحص GitHub Actions تلقائي لتدقيق TypeScript وبناء نسخة الإنتاج على Node.js 20.
- إصلاح أخطاء TypeScript المكتشفة أثناء تشغيل الفحص الآلي.
- اجتاز الفرع `rawda-2.0-ready` فحص `typecheck` وبناء الإنتاج في GitHub Actions بتاريخ 2026-11-25. هذا لا يعني أن الموقع منشور أو أن إعدادات OAuth والبريد قد اكتملت.

### متطلبات ما قبل الإطلاق التجاري

يلزم اختبار الأدوار والعزل بين حضانتين بحسابات فعلية واختبارات RLS آلية، وضبط Google OAuth والبريد على النطاق النهائي، وإكمال تخزين ملفات PDF والصور في Storage خاص، ولوحة إدارة المنصة المركزية والاشتراكات والفوترة والإشعارات، ثم نجاح `typecheck` و`build` والنشر.

لا تعتبر هذه النسخة خدمة منشورة أو جاهزة لاستقبال بيانات أطفال حقيقية قبل إكمال بوابات الإطلاق أعلاه.
