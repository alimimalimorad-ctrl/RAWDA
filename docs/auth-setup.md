# إعداد المصادقة في RAWDA

## طرق الدخول المعتمدة

- Email + Password: إنشاء حساب وتسجيل دخول بالبريد وكلمة المرور.
- Email OTP / Magic Link: إرسال رابط دخول إلى البريد للحسابات الموجودة.
- Google OAuth: تسجيل الدخول باستخدام Google عبر Supabase Auth.
- ولي الأمر: يسجل بالبريد أو Google، ثم يرسل طلب ربط من خلال معرّف الحضانة وكود الطفل. لا تظهر بيانات الطفل إلا بعد موافقة إدارة الحضانة.

## إعداد Supabase

1. أنشئ مشروع Supabase جديداً.
2. شغّل ملفات SQL من `README.md` بالترتيب حتى `008_parent_auth_linking.sql`.
3. من Authentication → Providers فعّل Email وGoogle.
4. اضبط Site URL وRedirect URLs لتشمل نطاق الإنتاج و`http://localhost:3000/auth/callback`.
5. أنشئ OAuth Client في Google Cloud، وأضف عنوان Supabase Auth callback الذي يظهر في صفحة Google provider إلى Authorized redirect URIs.
6. أدخل Client ID وClient Secret في إعداد Google provider داخل Supabase فقط.
7. للإنتاج: فعّل تأكيد البريد، واضبط SMTP موثوقاً مخصصاً.

## تدفق ربط الطفل

1. ينشئ ولي الأمر حساباً أو يسجل الدخول.
2. يفتح تبويب «كود الطفل» في صفحة الدخول.
3. يدخل slug الحضانة وكود الطفل.
4. ينشأ طلب pending في `parent_link_requests`.
5. بعد التحقق من هوية ولي الأمر، تعتمد إدارة الحضانة الطلب باستدعاء الدالة `review_parent_link_request(request_id, true)`؛ أو ترفضه باستدعاء الدالة مع `false`.
6. عند الاعتماد ينشأ الربط في `parent_children`، وتسمح سياسات RLS بعرض البيانات المصرح بها.

> لا تعتبر كود الطفل وحده إثباتاً كافياً للولاية. يجب على الحضانة التحقق من هوية مقدم الطلب قبل الاعتماد. واجهة مراجعة الطلبات الإدارية ليست ضمن هذه الحزمة بعد؛ يمكن للمطور بناءها على الدالة الآمنة أعلاه قبل الإطلاق العام.

## التحقق قبل النشر

- جرّب تسجيل حساب ببريد جديد وتأكيد البريد.
- جرّب كلمة المرور ورابط الدخول OTP.
- جرّب Google OAuth على نطاق الإنتاج.
- اختبر أن رابط callback لا يقبل مسارات إعادة توجيه خارج الموقع.
- أنشئ طلب ربط لطفل، وتأكد أن الحساب لا يرى الطفل قبل الموافقة.
- اختبر رفض الطلب، ثم الموافقة، ثم تأكد أن ولي الأمر لا يرى سوى الأطفال المرتبطين به.
